# Проверка браузерной диктовки на телефонах

Отдельная диагностическая страница: [открыть тест](https://anketa.vismuth.ru/api/main/public/voice-input-test). Backend-маршрут `GET /public/voice-input-test`, без JWT, отдаёт самостоятельный HTML через frontend rewrite. В рабочую анкету кнопка не добавлена.

Кнопка вызывает `SpeechRecognition` или `webkitSpeechRecognition` непосредственно внутри пользовательского нажатия. Язык `ru-RU`, одна фраза, промежуточные результаты отображаются; отдельного нажатия микрофона клавиатуры нет. Это проверка браузерного сервиса, своего распознавания/записи аудиофайла нет. Поддержка API сама по себе не доказывает работоспособность распознавания.

Результат виден как текст либо ошибка. Отчёт содержит название браузера/ОС, user agent, HTTPS, доступное имя API, времена событий, коды ошибок и число распознанных символов. Аудио и сам текст в отчёт не включены, на backend VISMUTH не отправляются и не сохраняются. Отчёт копируется пользователем вручную. Браузер может обращаться к своему внешнему сервису распознавания.

Страница обрабатывает отсутствие API, отказ разрешения, недоступность сервиса/микрофона, отсутствие речи, исключение запуска и минутный таймаут. При уходе со страницы распознавание прерывается. Ответ страницы `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`; индексирование и кеширование не требуются.

План реальной проверки: Chrome Android и Яндекс Android — у владельца; Safari iPhone — у его друга. Открывать в самом браузере, не во встроенном окне мессенджера. Нажать кнопку, разрешить микрофон, произнести предложенную нейтральную фразу, повторить при необходимости и скопировать отчёт для каждого браузера. Доступность страницы и автоматические проверки обработчиков не заменяют проверку реального микрофона. На момент публикации отчёты с реальных телефонов ещё не получены.
