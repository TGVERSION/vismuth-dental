# Продолжение диктовки после тишины

09.11.2026 в 21:45 Екатеринбург (16:45 UTC) опубликован `voice-pause-20261109T164402Z`. Предыдущий выпуск — `voice-transcript-20261109T162954Z`, исходная база Git — `4c0a819`.

По сообщению владельца Яндекс Браузер завершал ввод после пары секунд размышления. Причина в клиенте: событие завершения браузерного recognizer безусловно завершало всю пользовательскую диктовку. `continuous=true` не гарантирует, что мобильный провайдер оставит один сеанс открытым после тишины.

Теперь одна диктовка включает последовательные браузерные сеансы. После нормального `end` текущий снимок сохраняется в общий префикс, обработчики отсоединяются, новый recognizer запускается через 200 мс. Для пустого сеанса — задержка 1 с, чтобы избежать частых пустых повторов. `no-speech` с последующим `end` также продолжает диктовку. Панель, режим удержания/фиксации и таймер пользователя остаются активны.

Текст нового сеанса добавляется к завершённым фрагментам; повторы событий одного сеанса не вставляют его дважды, настоящие одинаковые слова между сеансами сохраняются. Поздние события старого recognizer проверяются по идентичности. Остановка во время ожидания сразу завершает ввод и отменяет будущий запуск; остановка активного recognizer ждёт последний результат до пяти секунд. Отмена, уход, ошибки разрешения/сети/микрофона и общий минутный лимит прекращают перезапуски. Лимит не сбрасывается при паузах, предупреждение о неподтверждённом хвосте сохраняется между сеансами.
