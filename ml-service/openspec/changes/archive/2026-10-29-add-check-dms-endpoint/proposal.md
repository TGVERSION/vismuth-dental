# Proposal

## Why

Для согласования услуг по ДМС нужно проверять, не назначены ли пациенту препараты и процедуры, которые не подтверждаются клиническими рекомендациями по его диагнозу. Сейчас в сервисе есть только проверка полноты протокола по одной захардкоженной базе (АГ), а она не отвечает на вопрос «лишнее ли назначение». Нужен отдельный независимый эндпоинт, который принимает PDF клинрека, код МКБ и текст назначений и возвращает размеченный текст: лишние позиции выделены, остальные не тронуты.

PDF передаётся файлом в самом запросе, а не ссылкой на S3: ml-service отвечает за собственную часть контура, и ему не нужен ни доступ к хранилищу, ни presigned-ссылки — так эндпоинт можно проверить независимо от backend.

## What Changes

- Новый `POST /check_dms` принимает `multipart/form-data`: файл PDF (до 30 МБ), `mkb` (строка «код + название») и `appointments` (свободный текст). Возвращает сегменты назначений с флагом `unnecessary` и фрагменты клинрека.
- PDF целиком читается в память, считается `sha256`, парсится из `BytesIO`; на диск файл не сохраняется.
- Новый пайплайн: проверка хэша в Qdrant → парсинг и чанкинг → эмбеддинги GigaChat (`EmbeddingsGigaR`, 2560 измерений) → upsert в локальный Qdrant (`storage/qdrant`) → retrieval по позициям назначений → LLM-вердикт.
- Разбиение `appointments` на позиции (split) через `GigaChat-3-Pro`; вердикт — через `GigaChat-3-Ultra` со структурированным выводом.
- Две новые роли LLM (`DMS_SPLIT`, `DMS`) и блок настроек в `GigaChatConfig`; существующие роли и промпты не меняются.
- Новые зависимости: `qdrant-client` (локальный режим), `pdfplumber` для парсинга с сохранением разделов и таблиц, `python-multipart` для приёма файла, `gigachat` для эмбеддингов.
- Хранилище `storage/qdrant` и том в `docker-compose.yml`; каталог PDF-кэша и обращение к S3 не нужны.

Legacy `/clinrec_checking/check`, Chroma-база и существующие промпты клинреков не затрагиваются.

## Capabilities

### New Capabilities

- `clinrec-dms-verification`: проверка назначений врача на соответствие клиническим рекомендациям по коду МКБ; разметка лишних позиций и возврат подтверждающих фрагментов.

### Modified Capabilities

Нет.

## Impact

- **API:** новый маршрут `POST /check_dms` (`multipart/form-data`); текущие маршруты не меняются.
- **Код:** `app/routers/check_dms.py`, `app/services/check_dms/` (приём файла, парсинг, чанкинг, индексация, retrieval, вердикт), `app/schemas/check_dms.py`, `app/config/dms_config.py`, `app/llm_services/llm_factory.py`, `app/services/prompts/`.
- **Зависимости:** `qdrant-client`, `pdfplumber`, `python-multipart`, `gigachat`.
- **Инфраструктура:** каталог `storage/qdrant`, том в `docker-compose.yml`; локальная модель эмбеддингов для ДМС не нужна (Qwen остаётся только в legacy-пути).
- **Внешние сервисы:** Qdrant (локально, без отдельного контейнера), GigaChat (`GigaChat-3-Pro`, `GigaChat-3-Ultra`, `EmbeddingsGigaR`). S3 из ml-service больше не используется.
- **Смежная зона:** backend для вызова эндпоинта должен отправлять файл вместо presigned-ссылки; это отдельная задача backend.
