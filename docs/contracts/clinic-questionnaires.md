# Анкеты для стоматологии (регистратура)

JWT + `is_clinic_admin` в этой клинике (или `super_admin`). Для клиники с `questionnaire_kind=dental` или `mixed`: регистратура создаёт пациенту персональную ссылку по ФИО, видит статус, печатает и отмечает подписанные анкеты. Код: `routers/clinic_questionnaires.py`, `services/questionnaire_invites.py`.

Как бумажная стоматологическая анкета, ссылка не привязана ни к врачу, ни к дате приёма: `doctor_membership_id` и `appointment_*` у такой анкеты пустые. Заполненную анкету видят все врачи клиники (см. [questionnaires.md](questionnaires.md)).

Ссылка `{FRONTEND_PUBLIC_URL}/q/i/{token}` показывается один раз: в базе лежит только хэш токена. Работает 7 дней с момента создания; незаполненная анкета после срока удаляется воркером. По бездействию такая анкета не бросается.

Статусы в списке: `invited` (ссылка отправлена) → `in_progress` (пациент начал) → `completed` (заполнена) → `printed` → `signed`.

## POST /clinics/{clinic_id}/questionnaires

- **Тело:** `last_name`, `first_name`, `middle_name?`, `birth_date?` (ISO-дата в прошлом, вводит администратор)
- **Ответ 201:** строка списка + `url`
- Новые приглашения создаются с `dental_answers.flow_version=2`: короткие страницы здоровья и уточнений. Существующие ссылки сохраняют свою версию; данные ранее заполненных анкет и печать не пересобираются автоматически.
- **Ошибки:** `400` нет фамилии/имени; `409` клиника не стоматологическая; `503` подписка клиники истекла

## GET /clinics/{clinic_id}/questionnaires

- **Query:** `status` (`invited | in_progress | completed | printed | signed`), `name` (часть фамилии, имени или отчества)
- **Строка:** `id, status, patient_last_name, patient_first_name, patient_middle_name, created_at, completed_at, printed_at, signed_at, invite_expires_at`; новые сверху, не больше 300

## GET /clinics/{clinic_id}/questionnaires/{id}

Строка + `structured`, `gaps` — карточка как у врача (для экрана и печати).

## POST /clinics/{clinic_id}/questionnaires/{id}/link

Новая ссылка `{url}`, прежняя перестаёт работать. `409` — анкета заполнена, `410` — срок ссылки истёк.

## POST /clinics/{clinic_id}/questionnaires/{id}/printed · /signed

Ставит `printed_at` / `signed_at` (повторный вызов не меняет время). `409` — анкета ещё не заполнена.

## DELETE /clinics/{clinic_id}/questionnaires/{id}

`204`. Ошибочная ссылка; заполненную удалить нельзя (`409`).

## Публичная сторона

`GET /public/invites/{token}` — см. [questionnaire-public.md](questionnaire-public.md). При `dental` общая ссылка клиники и врача закрыта: `GET /public/links/{slug}` → `blocked`, `block_code=invite_only`; `POST /public/questionnaires` → `403`. При `mixed` общие ссылки работают параллельно со стоматологическими приглашениями; начатые анкеты сохраняют свой `kind` при смене настройки клиники.

## Полнота результата и печать (31.10.2026)

Статус completed появляется после отправки последнего ответа, серверной проверки обязательных данных и успешного сохранения. Отдельного экрана проверки и дополнительного подтверждения пациентом нет (обновление 01.11.2026). Неопределённый медицинский ответ отображается отдельно от «нет» в карточке и в печатных данных. Конкретный аллерген сохраняется рядом с одной выбранной категорией; при нескольких категориях и общей подписи она выводится с оговоркой о неуточнённой связи. Собственный повод и дополнительные ответы включаются в дополнительные сведения.

43 строки основного бланка сохраняются. Для длинного открытого ответа интерфейс печатает явную ссылку на лист продолжения и весь исходный текст на продолжении; перед печатью показывает сообщение администратору. Исходные `paper_form` и сохранённые ответы при подготовке печати не изменяются, текст не обрезается. На продолжении есть ФИО, дата рождения и место для подписи. Количество страниц зависит от объёма ответа.

Дату рождения администратор вводит при создании ссылки вместе с ФИО. Она хранится в существующих dental_answers и попадает в печатную шапку, пациент её не заполняет и не перезаписывает. Поле необязательное для совместимости: без него дата в печати пустая. Миграции БД не требуется. Интеграции с МИС нет и не предполагается; автоматический перенос прежних медицинских ответов по имени не выполняется.

## Оператор и заполненные анкеты

Регистратура доступна также активному membership `is_operator` своей клиники через `require_clinic_registry`. Это не расширяет `require_clinic_admin`: управление клиникой, участниками и подпиской оператору недоступно. Super_admin работает с выбранной клиникой без membership; создание и перевыпуск ссылок сохраняют проверки подписки и сроков. Историческое чтение сохранившейся dental-карточки доступно super_admin.

Заполненные анкеты трёх видов доступны отдельно: `GET /clinics/{clinic_id}/completed-questionnaires` и `/{id}`. Фильтры, страницы и read-only семантика описаны в [questionnaires.md](questionnaires.md).

GET карточки для печати дополнительно принимает завершённые dental-анкеты прежнего публичного входа без персонального invite. clinic_id и права регистратуры проверяются по-прежнему; изменение статусов, перевыпуск и удаление ссылок используют прежний loader персональных приглашений.
