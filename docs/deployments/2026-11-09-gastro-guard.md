# Защита гастроопроса и поля интерфейса

09.11.2026 установлен `gastro-guard-20261109T042522Z` на `https://anketa.vismuth.ru`. Предыдущий выпуск — `auto-settings-20261109T034531Z`; исходная версия Git — `2f83159`. Итоговая проверка служб — 10:38 Екатеринбург, схема остаётся `0020_clinic_button_color`.

Обычная гастроанкета проверяет свободный ответ перед сохранением. Явно посторонние сообщения и команды изменить правила возвращают пациента к тому же вопросу: два предупреждения, остановка после третьего подряд либо шестого суммарно отказа. Принятый ответ сбрасывает последовательность. Отрицания, неизвестность, названия препаратов и необычные симптомы допустимы; сомнение классификатора не является нарушением. Сбой проверки даёт повтор без счётчика. Это вероятностная классификация, а не гарантия распознавания всех переформулировок.

Отклонённый текст не сохраняется. Служебный маркер имеет существующий `kind=fixed`, отдельный `step_key=guard_reject`, ключ вопроса в `choice` и необязательный UUID отправки. Он исключён из врачебной выдачи и суммаризации. Повтор UUID не вызывает новую проверку/нарушение. При остановке частичные данные сессии очищаются, кода и фоновой обработки нет; перезагрузка и POST остаются на экране остановки. Метаданные очищаются по сроку хранения. Лимит стоимости — 60 проверок/сессию/час. Прямой публичный доступ к внутреннему ML-маршруту закрыт, включая кодированные пути.

В ML добавлен изолированный классификатор с фиксированным системным prompt. Пациентские значения `state`/`known` вынесены из системных сообщений сбора в JSON пользовательского сообщения; суммаризация/уточнения не исполняют команды из данных. Медицинский текст и ошибки модели не логируются новой проверкой.

В интерфейсе поиск врача и специализация объединены в одно поле со сбрасываемой меткой. Исправлены курсоры действий и фокус внешнего округлого поля; внутренний input не рисует прямоугольник. В общем `CustomDropdown` фокус расположен на округлом триггере. Исключение поля сообщения чата сохранено.
