# Proposal

## Why

Для согласования услуг по ДМС нужно проверять, не назначены ли пациенту препараты и процедуры, которые не подтверждаются клиническими рекомендациями по его диагнозу. Сейчас в сервисе есть только проверка полноты протокола по одной захардкоженной базе (АГ), а она не отвечает на вопрос «лишнее ли назначение». Нужен отдельный независимый эндпоинт, который принимает PDF клинрека, код МКБ и текст назначений и возвращает размеченный текст: лишние позиции выделены, остальные не тронуты.

## What Changes

- Новый `POST /check_dms`: принимает `pdf_url` (presigned S3), `mkb` (строка «код + название») и `appointments` (свободный текст), возвращает сегменты назначений с флагом `unnecessary` и фрагменты клинрека.
- Новый пайплайн: скачивание PDF → проверка хэша в Qdrant → парсинг и чанкинг → эмбеддинги `Qwen3-Embedding-0.6B` → upsert в локальный Qdrant (`storage/qdrant`) → retrieval по позициям назначений → LLM-вердикт.
- Разбиение `appointments` на позиции (split) через `GigaChat-3-Pro`; вердикт — через `GigaChat-3-Ultra` со структурированным выводом.
- Две новые роли LLM (`DMS_SPLIT`, `DMS`) и блок настроек в `GigaChatConfig`; существующие роли и промпты не меняются.
- Новая зависимость: `qdrant-client` (локальный режим) и `pdfplumber` для парсинга PDF с сохранением структуры разделов и таблиц.
- Хранилище `storage/` (Qdrant + кэш PDF), том в `docker-compose.yml`.

Legacy `/clinrec_checking/check`, Chroma-база и существующие промпты клинреков не затрагиваются.

## Capabilities

### New Capabilities

- `clinrec-dms-verification`: проверка назначений врача на соответствие клиническим рекомендациям по коду МКБ; разметка лишних позиций и возврат подтверждающих фрагментов.

### Modified Capabilities

Нет.

## Impact

- **API:** новый маршрут `POST /check_dms` в ml-service, обратносовместимый с текущими маршрутами.
- **Код:** `app/routers/check_dms.py`, `app/services/` (загрузка, парсинг, чанкинг, индексация, retrieval, вердикт), `app/schemas/check_dms.py`, `app/config/`, `app/llm_services/llm_factory.py`, `app/services/prompts/`.
- **Зависимости:** `qdrant-client`, `pdfplumber`; `httpx` для скачивания уже есть.
- **Инфраструктура:** каталог `storage/` (Qdrant, PDF-кэш), том в `docker-compose.yml`; модель `Qwen3-Embedding-0.6B` переиспользуется из `llm_setup`.
- **Внешние сервисы:** Qdrant (локально, без отдельного контейнера), S3 (presigned GET), GigaChat (`GigaChat-3-Pro`, `GigaChat-3-Ultra`).
